Redrob Cowork is a desktop app plus a local `redrob-server`, running the Redrob Code
engine as a sidecar. Everything happens on your own machine, against your own files.
There is no account, no organization, and no hosted control plane, and none is planned.

Last updated: August 2026

<Info>
  **Live** means available today. **Preview** means present but rough. **Partial** means supported with limitations. **Building** means active work. **Next** is the next thing we intend to pick up. **Exploring** is a direction, not a commitment.
</Info>

## Redrob Cowork as an MCP surface

The app is an MCP client for the servers you add, and it exposes its own UI as a local
MCP server so other agents can drive it.

| Capability | What it does | Status |
| --- | --- | --- |
| Workspace MCP connections | Add any MCP server to a workspace, with OAuth handled locally. | Live |
| `redrob-ui-mcp` | A local stdio server that lets OpenCode, Claude Code, Codex, Cursor, VS Code, Windsurf, Zed, and Gemini CLI read app context and run named UI actions. | Live |
| Semantic UI control for in-app agents | The workspace agent drives the app through affordance ids rather than pixels. | Live |
| Portable skills | Skills are plain `SKILL.md` files, so a repository or a plugin bundle is all it takes to hand one over. | Live |
| Git-based plugin publishing and refresh | Install from a repository today; reinstall by hand to update. | Building |

## MCP spec compliance

Redrob Cowork implements the [MCP authorization specification](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization)
as an MCP client, so the desktop app can connect to a compliant server or an enterprise
MCP gateway. Items marked Building or Next track the 2026-07-28 MCP specification
release.

| Capability | What it does | Status |
| --- | --- | --- |
| OAuth 2.1 self-discovery | Connect to a compliant MCP server or enterprise MCP gateway with just its URL: `WWW-Authenticate` challenge, Protected Resource Metadata (RFC 9728), Authorization Server Metadata (RFC 8414), and Dynamic Client Registration (RFC 7591). | Live |
| PKCE and resource indicators | PKCE (S256) enforced on all authorization flows, with RFC 8707 resource indicators on authorization and token requests. | Live |
| Silent session renewal | Short-lived access tokens backed by rotating refresh grants with replay protection, so connections renew without re-prompting for login. | Live |
| Manual client credentials fallback | Enter a client ID and secret for authorization servers that do not offer Dynamic Client Registration. | Live |
| `application_type` declaration (SEP-837) | Declare native or web application type during Dynamic Client Registration for compatibility with OIDC-backed enterprise authorization servers. | Building |
| Client ID Metadata Documents (SEP-991) | A single, stable HTTPS client identity that enterprises allowlist once, replacing per-connection registrations and wildcard redirect allowlists. | Building |
| Issuer-bound credentials (SEP-2352) | Key stored client credentials to the issuing authorization server and re-register automatically when a server's authorization server changes. | Building |
| Authorization hardening (SEP-2468, SEP-2207) | Validate the `iss` parameter on authorization responses (RFC 9207) and adopt clarified refresh-token scope semantics. | Next |

> Following the spec is what makes Redrob Cowork drop-in compatible with enterprise MCP
> gateways: paste the gateway URL, sign in with your identity provider, and every
> downstream system it fronts becomes available.

## Deploying it across a fleet

Redrob Cowork installs per machine, so a rollout is an installer and configuration
problem, not a hosted service problem.

| Capability | What it does | Status |
| --- | --- | --- |
| Enterprise desktop deployment | MDM distribution and a `desktop-bootstrap.json` reference for preconfiguring installs. | Live |
| Air-gapped and private-network installs | Documented outbound requirements, certificate trust, and proxy handling. | Live |
| On-prem branding | Replace names, wordmarks, and desktop icons inside your own deployment. | Live |
| Self-hosted remote runtime | Run the server side on your own infrastructure and point the desktop at it. | Partial |

See [Self-host](/start-here/self-host) for what that involves today.

## Not on the roadmap

These existed in an earlier hosted version of Redrob Cowork and are not coming back:

- Accounts, sign-in, organizations, teams, and roles.
- A hosted control plane for distributing skills, connections, or policies.
- A hosted MCP endpoint other clients can point at.
- Hosted workspaces and remote workers.
- Scheduled and event-triggered runs inside the app. Drive recurring work from your own
  scheduler through [redrob-ui-mcp](/model-context-protocol/overview).
