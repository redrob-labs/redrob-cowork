<Note>
**Skills are files in your workspace.** Redrob Work writes each skill to
`.opencode/skills/<skill-name>/SKILL.md` under the workspace root. There is no
account, no organization, and no remote copy. Nothing leaves your machine.
</Note>

Do the work once in chat before you turn it into instructions.

## Turn a useful chat into a skill

1. Finish the task in chat and keep the thread open.
2. Ask in plain English: `Turn what we just did into a reusable skill`.
3. Redrob Work writes `.opencode/skills/<skill-name>/SKILL.md` in the current
   workspace, validates the frontmatter, and reads the file back to confirm it.
4. Give the skill a clear name if Redrob Work asks. In the desktop app you get a
   confirmation card with the skill name and a link to it in your Library.
5. Use it later by name in chat, or describe the same kind of task and let Redrob Work
   trigger it when it matches.

## Other ways to create a skill

- **From the Library**: open `Settings` > `Library`, filter to `Skills`, and click
  `Add skill`. Same result, same location on disk.
- **By hand**: create `.opencode/skills/<name>/SKILL.md` yourself. The frontmatter
  needs a `name` matching the directory and a `description` telling the agent when to
  use it.

## Where Redrob Work looks for skills

The Library lists skills from the current workspace and its parent directories up to
the `.git` boundary:

- `.opencode/skills/` and `.claude/skills/` in the project, shown as project scope.
- `~/.config/opencode/skills/`, `~/.claude/skills/`, `~/.agents/skills/`, and
  `~/.agent/skills/`, shown as global scope.

Project skills win when a name appears in both places.

## Change it or hand it to someone else

1. To refine it, ask for the change in chat, such as
   `Make the skill ask before sending email`. Redrob Work edits the same file.
2. To hand it to a teammate, see
   [Share and copy a skill](/start-here/do-work-with-it/publish-and-copy-a-skill).

<Note>Creating a skill changes nothing outside your workspace. Sharing is a separate step you choose.</Note>
