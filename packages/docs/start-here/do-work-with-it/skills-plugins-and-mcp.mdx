---
title: "Connections, skills, and plugins"
description: "Use connections to reach a system and skills to make it usable, then bundle both into a plugin"
---

Redrob Cowork gives agents a small set of building blocks. The connection reaches the
system, the skill is how the work gets done, the plugin is the bundle, and the Library is
where you see what you have. All four are local to your machine.

## Choose the right unit

| Use | Means | Reach for it when |
| --- | --- | --- |
| Connection | An MCP server you add to a workspace, signed in as you. | The agent needs to act in that system. |
| Skill | Written instructions the agent loads when a task matches. A file at `.opencode/skills/<name>/SKILL.md`. | One repeatable way of doing work should be written down once. |
| Plugin | A bundle of skills, commands, agents, and MCP servers packaged as one installable thing. | Several related pieces should travel together. |
| Library | The list of what this workspace actually has, in `Settings` > `Library`. | You want to see or manage what is already available. |

MCP is the open standard underneath every connection. Day to day you can think in
terms of connections, skills, plugins, and your Library.

## Where skills come from

The **Skills** screen lists every skill in the workspace and where it came from:

- **Library**: the default skills from the Redrob Console, filed by profession, task and
  language. Press **Add** to copy one into the workspace. When the Console cannot be reached,
  the screen shows the copy of the library that ships with the app.
- **Team**: the skills your team keeps in the Redrob Console for the workspace your Redrob
  Key belongs to. They are installed and kept up to date on their own, about every 30
  minutes, and are changed in the Console, not here. A skill of your own with the same name
  always wins.
- **Mine**: skills you write with **New skill**, or with **Save as skill** on a message you
  sent.

Every skill is a `SKILL.md` file in `.opencode/skills/<name>/`. Open one to read its
instructions, **Run** it in a new chat in Plan mode, or put it on a schedule. Type `/` in
the composer to use a skill in the chat you are in.

## Connect the system first

Open `Settings` > `Library`, expand `Advanced settings`, and click `Add workspace MCP`.
For the click-by-click flow, see
[Add an MCP server](/start-here/connect-your-stack/add-an-mcp-server).

Everything the agent can use is listed in `Settings` > `Library`. There is no catalog
of services waiting to be enabled: what you add is what you have.

## Add skills when the connection is thin

A connection may reach your ticketing system but still be awkward: an incident may need
exact fields, a priority change may need a safe sequence, or one ticket action may
behave badly.

Write skills for those system rules:

- how to file an incident with the right fields;
- how to update a customer note without losing context;
- how to work around an unreliable ticket action.

These skills describe the system, not one person's style, so everyone who uses that
system needs them.

## Bundle system skills into a plugin

The useful plugin case is a thin connection plus several system skills. If half a dozen
ticketing skills make one system usable, bundle them into one plugin, the ticketing
unit, and share that single thing. A plugin can carry its MCP servers in `.mcp.json`,
so installing it registers the connection too.

For distribution, see
[Share and copy a skill](/start-here/do-work-with-it/publish-and-copy-a-skill).

## Keep personal skills separate

Use connections for systems. Use plugins to bundle the skills that make a system
usable. Personal or workflow-specific skills can stay individual unless a team should
receive them together.
