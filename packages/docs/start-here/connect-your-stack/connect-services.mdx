<Info>
**Everything here is local.** Redrob Cowork has no account, no organization, and no
service catalog. You connect a service by adding its MCP server to a workspace, and
the credentials stay in your own `redrob-server` store.
</Info>

The Redrob Cowork agent reaches other systems through MCP servers you add yourself.
Slack, Notion, Linear, GitHub, an internal API, a local script: if it speaks MCP, the
agent can use it.

## Add a connection

1. Open the Redrob Cowork desktop app.
2. Go to `Settings` > `Library`.
3. Expand `Advanced settings` and click `Add workspace MCP`.
4. Enter a name and the server URL, and say whether the server needs OAuth.
5. If it does, finish the provider's approval page in your browser. It redirects back
   to Redrob Cowork and the connection moves to ready.

The step-by-step version with screenshots is
[Add an MCP server](/start-here/connect-your-stack/add-an-mcp-server). For a worked
example with a real provider, see
[Connect Slack as a custom MCP](/start-here/connect-your-stack/connect-slack-mcp).

## Ask your agent to use it

You do not need to know a server name or a tool name. Ask for the outcome you want:

- "Find the Q3 launch page in Notion."
- "Open a Linear issue for the crash I just described."
- "Post the summary to the release channel."

The agent searches the tools its connected servers expose, then calls an exact match.
If a connection needs attention, it points you back to `Settings` > `Library` with the
action to take.

## Connections, plugins, and the Library

- A **connection** is one MCP server added to one workspace, signed in as you.
- A **skill** is written instructions the agent loads when a task matches. Skills are
  files in your workspace, under `.opencode/skills/<name>/SKILL.md`.
- A **plugin** bundles skills, commands, agents, and MCP servers so they travel
  together. Redrob Cowork installs Anthropic-compatible plugin bundles from public
  GitHub repositories.
- The **Library** (`Settings` > `Library`) is the single list of what this workspace
  has: skills, commands, agents, MCP connections, and plugins.

## What is not here

Redrob Cowork does not host a shared service catalog, and it does not publish a remote
MCP endpoint for other clients. If you want another MCP client to drive Redrob Cowork
itself, that runs the other direction over a local stdio server: see
[Control Redrob Cowork from any MCP client](/model-context-protocol/overview).
