---
title: "Migrate from Claude Cowork"
description: "Move your files, skills, plugins, MCP servers, and team setup to Redrob Work."
---

You do not need to rebuild your setup to move from Claude Cowork to Redrob Work. Start with one real task, bring over the capabilities it needs, and keep Cowork available until that task works end to end.

## What carries over

| From Claude Cowork | In Redrob Work | What to do |
| --- | --- | --- |
| Local files and folders | Workspace files | Open the same folder or repository as an Redrob Work workspace. |
| `SKILL.md` skills | Skills | Copy the skill folder into your workspace or install it as a plugin. |
| Claude-compatible plugins | Plugins | Import the plugin from its public GitHub repository; Redrob Work normalizes its skills, commands, agents, and MCP dependencies. |
| MCP servers | Workspace MCP connections | Add the server URL to the workspace and sign in again. |
| Claude models | Anthropic provider | Add your own Anthropic API key. |
| Scheduled tasks | Not available | Redrob Work has no scheduler. Trigger the work from chat, or drive it from outside with your own cron plus an MCP client. |

<Note>
  Conversation history does not transfer automatically. Keep any important instructions in workspace files or skills rather than relying on an old thread.
</Note>

## 1. Install Redrob Work and open the same work

1. [Download Redrob Work](https://redrob.io/download) for macOS, Windows, or Linux.
2. Create a workspace from the folder or repository you used with Cowork.
3. Ask Redrob Work to summarize the workspace before changing anything. This confirms it can read the files you expect.

Your files stay where they already are. Redrob Work does not require you to upload a duplicate copy before you can work with them.

## 2. Choose your models

Redrob Work is model-agnostic. You can keep using Anthropic models, add another provider, or let your organization provision models centrally.

- To keep using Claude, follow [Add an Anthropic API key](/start-here/connect-your-stack/add-anthropic-api-key).
- To use ChatGPT, follow [Sign in with ChatGPT](/start-here/connect-your-stack/sign-in-with-chatgpt).
- For another provider, follow [Add a custom LLM](/start-here/connect-your-stack/add-a-custom-llm).
- For Redrob's own models, paste a Redrob Key from [console.redrob.ai](https://console.redrob.ai) on the connect screen.

Your Claude subscription and Anthropic API billing may be separate. Confirm API access before removing Cowork from your workflow.

## 3. Bring over skills and plugins

Redrob Work uses the same `SKILL.md` format. Copy a skill directory into the workspace, or import the plugin that contains it.

After importing each skill:

1. Open the skill and check any file paths, app names, or environment variables.
2. Run the smallest task that should trigger it.
3. Confirm the output before importing the next skill.

See [Connections, skills, and plugins](/start-here/do-work-with-it/skills-plugins-and-mcp) for how Redrob Work organizes these pieces. For handing them to teammates, see [Share and copy a skill](/start-here/do-work-with-it/publish-and-copy-a-skill).

## 4. Reconnect apps and MCP servers

Credentials do not move between products. Reconnect each service so Redrob Work receives its own authorized access.

- For the vocabulary and the general flow, read [Connect your services](/start-here/connect-your-stack/connect-services).
- For each remote or local MCP server, use [Add an MCP server](/start-here/connect-your-stack/add-an-mcp-server).
- To hand the same set of servers to teammates, bundle them in a plugin repository: [Share and copy a skill](/start-here/do-work-with-it/publish-and-copy-a-skill).

Test read-only actions first. Then test actions that modify data, such as sending a message or updating a record, with a disposable example.

## 5. Replace schedules and move browser tasks

Redrob Work does not run work on a schedule. For every recurring Cowork task, decide
whether it becomes a skill you trigger from chat, or a job you drive from outside the
app. For the second option, your own scheduler can start an MCP client that calls
Redrob Work through [redrob-ui-mcp](/model-context-protocol/overview).

For browser-driven work, follow
[Control the browser](/start-here/do-work-with-it/control-the-browser) and verify the
target site while you are present.

## 6. Move a team without configuration drift

There is no central place to assign a setup, so make the setup itself portable.

- Commit skills to the repository the team already shares. Everyone who clones gets
  them.
- Package anything larger as a plugin repository on GitHub and have people install it
  once: [Share and copy a skill](/start-here/do-work-with-it/publish-and-copy-a-skill).
- Keep model and service credentials per person. Each teammate connects their own.

## Cutover checklist

- [ ] The same workspace opens and the agent can read the expected files.
- [ ] At least one model is connected and billing is understood.
- [ ] Each required skill triggers on a representative task.
- [ ] Each MCP server is authorized and tested.
- [ ] Every recurring Cowork task has a replacement: a skill, or an external trigger.
- [ ] Shared skills live in a repository or plugin bundle, not in one person's folder.
- [ ] Important Cowork instructions are saved in files or skills.
- [ ] Cowork remains available until the representative workflow passes in Redrob Work.

Once the checklist passes, make Redrob Work the default for that workflow and migrate the next one.
