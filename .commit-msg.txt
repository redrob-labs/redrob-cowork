refactor: rename the product to Redrob Cowork

1,710 occurrences across 334 files: "Redrob Work" -> "Redrob Cowork" and
"레드롭 워크" -> "레드롭 코워크".

Display strings only. The functional identifiers are untouched, and they are
safe by construction rather than by an exclusion list, because none of them
contains the string that was replaced: io.redrob.work (the appIdentifier that
owns the userData directory, so existing installs keep their data),
cdn.redrob.ai/work/ (the updater feed path, so shipped clients keep updating),
the @redrob/* package scope, and the REDROB_* env prefix. Counts after the sweep
are unchanged: 25, 10, 87 and 239 files respectively.

Four places had to move together or the build breaks in ways tests would not
catch, and they did: electron-builder productName, desktop-distribution.mjs
appName (the window title, which .opencode skills match on), the
"Redrob Cowork Computer Use.app" helper bundle name in three files that must
agree (the prepare script that creates it, the after-sign script, and the
packaging filter glob), and the "Redrob Cowork.app" path the migration validator
looks for inside a release zip.

Historical records are excluded: .agents/ finished task logs keep the name the
work actually shipped under, since rewriting them would claim a name that never
existed at that date.

scripts/check-brand.mjs is the gate that keeps this from being undone one file at
a time -- a copy-pasted string, a doc written from memory, a merge resurrecting
an old hunk. It runs in the i18n workflow, which is a required check on every
pull request, and was reverse-verified by injecting the old name.

Known failure NOT caused by this change: apps/desktop nuke.test.mjs
"buildNukeManifest still wipes a dev profile's own orchestrator data dir" fails
identically on the trunk (verified by running it there), so it is pre-existing
and needs its own fix.
