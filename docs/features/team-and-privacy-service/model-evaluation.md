# Privacy model measurement (C5)

Which pretrained model, if any, ships in the installer (C8). No model was fine-tuned: each candidate is measured as published, in the runtime redrob-server ships.

Reproduce it:

```sh
uv pip install -r apps/server/scripts/privacy-model/requirements.txt
python apps/server/scripts/privacy-model/prepare.py   # downloads and exports to apps/server/.privacy-models/
pnpm privacy:eval --threads 4                         # bundles src/privacy/eval/run.ts, runs it under Node
```

Result: `1T/veil-pii-ko-lite`, exported by prepare.py (`veil-ko-lite`, 103 MB), is the recommended model. It meets the bar, and it is the only candidate that also finds addresses (94.5%). `klue-ner-base` meets the bar on names but finds 19.8% of addresses. The small models are fast but miss English names. `-shipped` rows are the int8 file each repo publishes itself, measured as is: veil's is 143 MB, over the size limit.

Latency is right at the bar: 150 ms median per 1,000 characters on an Apple M3 with 4 threads, measured with a load average of about 5 from other work on the machine (the first run, at load 4.5, gave 145-220 ms). The gate reads each text once per chat (results are cached per text), so the cost is paid on the first send of an attachment, about 7.5 seconds for a 50,000-character contract at High or Strict.

Findings along the way:
- Dynamic int8 quantisation (activations included) lost about 15 points of name recall, so prepare.py quantises the weights only: 8-bit matmuls and 4-bit embeddings.
- onnxruntime-web (WebAssembly) took 960-2,460 ms per 1,000 characters, so it was rejected. The desktop app runs the server inside Electron (Node), where onnxruntime-node loads natively. A bun-compiled server binary cannot load it (the dylib is not found), so that build falls back to patterns only and `GET /privacy/detector` says so.
- The decoder cut names that end in a particle-like syllable (손하은 became 손하) and split addresses and organisations at punctuation. The fixed decoder raised name recall from 95% to 98%; `detector.test.ts` pins both.
