# Privacy model measurement (C5, work in progress)

This is the first measurement. The detector is wired into the gate; the integration tests and the decision about which model ships (C8) are still open.

Reproduce it: `uv pip install -r apps/server/scripts/privacy-model/requirements.txt`, then `python apps/server/scripts/privacy-model/prepare.py`, then run `src/privacy/eval/run.ts` under Node (bundle it with bun build first).

Findings:
- Dynamic int8 quantisation (activations included) lost about 15 points of name recall, so prepare.py now quantises the weights only: 8-bit matmuls and 4-bit embeddings, about 103 MB.
- onnxruntime-web (WebAssembly) took 960-2,460 ms per 1,000 characters, so it was rejected. The desktop app runs the server inside Electron (Node), where onnxruntime-node loads natively. A bun-compiled binary cannot load it, because the dylib is not found, so that build falls back to patterns only.
- Latency on an Apple M3 with 4 threads is 145-220 ms because of background load (load average about 4.5). The two base-size models are the same architecture and run at the same speed.
